## Czysty checkout

Zainstaluj Git, PowerShell 7 oraz SDK wskazane w `global.json`. Uruchom `pwsh -File scripts/check-repository.ps1`, `dotnet restore ServerDesk.sln --locked-mode`, `dotnet build ServerDesk.sln -c Release --no-restore -m:1` i `dotnet test tests/ServerDesk.Tests -c Release --no-build`. Lokalne SDK i pobrane biblioteki w `.tools` są opcjonalne; nie kopiuj ich do repozytorium. Pełną macierz CI definiuje [ci.yml](../.github/workflows/ci.yml), a strukturę dokumentacji [indeks](README.md).

Narzędzia SSH domyślnie używają aliasu `serverdesk_fixture`, niezależnego od loginu systemowego. Dla innego serwera fixture ustaw `SERVERDESK_TEST_SSH_USER`. Skrypty NSS uruchamiane przez sudo wybierają zwykłego użytkownika z `SUDO_USER`; opcjonalny `SERVERDESK_TEST_OS_USER` wskazuje inne istniejące konto testowe. Nie modyfikują kont systemowych. Domyślnie SSH, test hasła i SNMP nasłuchują tylko na `127.0.0.1`; `SERVERDESK_TEST_LISTEN_ADDRESS` służy do jawnego wskazania adresu izolowanego laboratorium.

`ServerDesk.RdpProbe` przy opcjonalnym `--auth` korzysta z zainstalowanego `xfreerdp3` (Linux lub domyślne WSL na Windows). `SERVERDESK_TEST_FREERDP` może wskazać inny plik wykonywalny w tym środowisku, a `SERVERDESK_TEST_WSL_DISTRO` — konkretną dystrybucję. Odcisk certyfikatu i login przekazuje się jawnie, hasło tylko przez stdin. Nie zawiera ścieżek do komputera autora ani zapamiętanego certyfikatu.

Secret Service integration: prepare-secret-service.sh pobiera paczki GNOME/libsecret tylko do .tools; apt działa z --download-only, bez instalacji i zmian osobistego keyringu. Publikacja narzędzia: `dotnet publish tools/ServerDesk.SecretProbe -c Release -r linux-x64 --self-contained true -o artifacts/secret-probe-linux`. `bash scripts/test-secret-service.sh` tworzy jednorazowe D-Bus/XDG i keyring, następnie zamyka daemon i usuwa katalog testowy. Nie zmienia HOME. Nie używaj normalnego magazynu użytkownika do tego testu.

Desktop UX: UiSmoke `ROOT --platform-ux` sprawdza PL/EN, pięć motywów, tekst 16, modelowane przejścia DPI/odłączenie monitora, przywracanie limitów dialogu, długie potwierdzenia, klawiaturę i zwalnianie zamkniętych okien. Nie modyfikuje ustawień ekranów OS i nie jest próbą fizycznych monitorów ani czytnika ekranu. `ROOT HOST KEY --session-endurance 10` zapisuje dodatkowo CPU znormalizowany do liczby CPU procesu, working set i `endurance-closed.json`. Linux: `bash scripts/check-linux-desktop.sh [EXE]` wykonuje odczytowy preflight; [macierz i checklista natywnego desktopu](platform-support.md).

test-freerdp-cli.sh pobiera izolowany klient i sprawdza pomoc oraz argumenty przeciw nieużywanemu portowi loopback. Oczekiwany błąd połączenia jest kontrolą uruchomienia, nie testem protokołu. Rzeczywiste RDP sprawdzono na udostępnionym serwerze: FreeRDP/WSLg w 0.14.0 i osadzony komponent Windows w 0.15.0/0.15.1. UiSmoke.exe z `artifacts/ui-rdp-native --native-rdp` sprawdza kontrolkę bez sieci; `HOST LOGIN --desktop` dodaje test logowania. Uruchomienie przez dotnet.exe nie sprawdza manifestu EXE aplikacji. Od 0.15.1 wydanie sprawdza `scripts/test-windows-manifest.ps1`, a `dotnet tools/ServerDesk.AppProbe/bin/Release/net10.0/ServerDesk.AppProbe.dll EXE REPORT [HOST USER]` uruchamia kontrolę w samym opublikowanym EXE. Opcjonalne hasło jest czytane bez echa, przesyłane przez pipe dla bieżącego użytkownika i nie zapisywane. Test używa osobnego katalogu danych. UiSmoke/Framework-dependent EXE wymaga lokalnego runtime; ustaw DOTNET_ROOT_X64 na `.tools/dotnet`, jeśli runtime nie jest zainstalowany. Wydanie self-contained nie wymaga tej zmiennej.
