# ServerDesk Public Beta — known issues

- **Diagnostics and profile deletion (0.42.0):** missing credential directories no longer block saved-profile deletion. Settings provides a bounded log preview and full-copy export; exported logs can contain addresses and paths, so review them before sharing. Stable symlink/junction aliases are resolved before export. This is not protection against a hostile process changing directory links concurrently. Native VM/hardware and long-running acceptance remain pending. See the [current verification scope](reports/release-verification-0.42.0.md).

This is a public beta. Keep a backup before upgrading and validate the workflows you need in a test environment.

- **1.0 preparation (0.41.0):** native VMware/hardware acceptance is deferred at the maintainer's request. Windows/Linux automated checks and Ubuntu/WSL do not certify native Kali/KDE, clean-VM installer registration, physical Serial, mixed-DPI monitors or multi-hour pilot sessions. A failed collection-index write preserves its saved secret; after a committed deletion, an unavailable credential provider can leave an unused encrypted blob. Database backups still exclude those blobs. See the [release verification scope](reports/release-verification-0.41.0.md).

- **Customization and backup checks (0.40.0):** interface fonts depend on local availability and fall back to the default family. Changes preview live; Cancel restores the previous appearance. Check backup verifies SQLite structure/schema, not application content or secrets. Restore remains manual; see [database backups](database-backups.md). Diagnostic cancellation drains owned work; an uncooperative provider may take time to finish.

- **Exports and saved diagnostics (0.39.1):** configuration, Commands and Network Tools exports require a filesystem path. A completed temporary file replaces the destination after success; this is not a power-loss guarantee, and a hard process termination may leave `.part` files. New Unix files use owner-only permissions; exports remain plaintext. Invalid saved diagnostic data is preserved and reported instead of automatically reset. A diagnostic can complete with a warning if optional history/preferences persistence fails.

- **Desktop acceptance (0.38.0):** dialogs react to monitor/DPI changes and restore resize limits. Automated mixed-scale tests are simulated; physical monitors, screen readers and native Kali/KDE/Wayland remain unverified. This build uses X11/XWayland and Secret Service, without a direct KWallet backend. See the [platform matrix and acceptance checklist](platform-support.md).

- **Connection browser (0.37.0):** filtering clears a hidden server selection; select a visible profile again before connecting. Search expansion is temporary and does not replace normal folder collapse state. Automated PL/EN tests cover sort/reload/filter/restart; physical drag and drop and very large folder trees still need wider acceptance.

- **Database snapshots (0.37.0):** manual backups are available in Settings → Security; an existing database is backed up before a schema migration. These snapshots include committed WAL data and database metadata, but exclude OS credential-store contents and private keys. They do not replace a full data backup. Restore instructions and limitations: [database backups](database-backups.md).

- **Split workspace:** up to four docked panels. Three-panel mode uses a tall left panel; grid mode is 2×2. At small sizes, toolbars wrap and terminal space decreases; hiding the sidebar helps. Layout changes keep live sessions, but physical cross-window drag gestures and mixed-monitor DPI need wider testing. New snapshots are backward-readable by 0.35.0; older builds may reject the new layout values. Keep a backup before downgrading.

- **Session preferences:** cursor changes preview live; the scrollback limit applies on the next SSH/Serial connection. SFTP defaults apply only on first opening in a tab. Remote applications can override cursor appearance. Local start directories are device-specific; an unavailable directory falls back to home with a warning. Native folder-picker gestures and physical serial adapters need wider manual coverage.

- **VNC:** classic password/no-authentication RFB only. No TLS/VeNCrypt or server identity verification; protect the connection with a VPN or an existing tunnel. No VNC clipboard or file transfer. Tight and ZRLE are disabled; Raw/CopyRect/ZLib are used.
- **RDP:** embedded on Windows and on Linux through X11 FreeRDP (`xfreerdp3`/`xfreerdp`) and XCB. Wayland sessions require XWayland; native Wayland embedding is not implemented. Linux credentials and exceptional certificate consent use ServerDesk dialogs. Consent is scoped to the current tab, and normal system CA/hostname verification still applies. Linux reconnection is manual; clipboard and shared folders depend on the installed client/server. Linux file drag-and-drop into RDP is not implemented. AD/Microsoft accounts, all remote clipboard formats, physical drag and drop and mixed-DPI monitors are not fully covered by the acceptance matrix. There is no bundled FreeRDP binary.
- **Serial:** software and pseudo-terminal tests; broad physical adapter/hardware testing remains outstanding. Linux users need permissions for their device (often the `dialout` group).
- **SSH input:** real password/key OpenSSH, vim/nano/top/htop/MC/bash/zsh/fish and synthetic keyboard/clipboard events were tested on Windows and Ubuntu/WSL. Physical AltGr/IME/layout combinations, terminal mouse gestures and all extended keyboard-protocol options need further acceptance. A committed UTF-8 text test does not validate a physical input method.
- **Terminal search:** searches available SSH/Serial scrollback, excluding already discarded history. Literal queries are limited to 256 UTF-16 code units; the emulator caps physical highlight runs at 10,000, so wrapped matches can reach the cap sooner. Results are refreshed explicitly after new output or on navigation. Complex combining/ZWJ sequences depend on the emulator's search support and are not fully covered.
- **Monitoring:** Linux /proc and standard command formats are assumed. Missing CPU/RAM/df/ip/lscpu sections are marked individually; MemFree is an explicitly labelled estimate. A lost established monitoring connection retries after a 30-second backoff plus the configured sample interval. An initial monitoring connection error can be retried by opening Monitoring. Passphrase preparation runs off the UI, but an already-started third-party key read/derivation must finish before cancellation can release its resources. Restricted-PATH fixtures do not replace acceptance on every distribution.
- **SFTP:** symbolic-link details/navigation, remote creation and explicit copying of a selected resolved target's contents are supported. Recreating link objects across platforms is unsupported; nested links remain skipped. Transfers have a 20,000-entry/64-level limit per job; partial completed work is preserved after a failure. Deletion/rename preserve links themselves; checks do not protect against every concurrent filesystem race. A lost connection can leave a remote temporary `.part` file. A server without safe atomic rename may refuse an overwrite and preserve the original file.
- **Credentials:** Windows DPAPI is tied to the Windows user/machine. Linux persistence needs `secret-tool` and an unlocked Secret Service. KWallet compatibility depends on its Secret Service interface. A JSON profile export does not include passwords or private keys.
- **File navigation:** each panel retains up to 100 successful paths in memory, cleared on reconnect/close. Both directory listings refresh together; failure rolls back unchanged inputs to the last confirmed paths. Draft paths must be confirmed with Enter before file operations; Escape restores the open directory. This does not eliminate concurrent server/filesystem races.
- **Workspace:** tabs are restored without automatically connecting. Long sessions, large server trees, accessibility and every physical keyboard/display combination need wider user feedback.
- **Language restart:** active tabs require confirmation before sessions/transfers disconnect. The replacement waits up to two minutes for the old process to exit. If shutdown hangs beyond that limit, close the old instance and start the app manually; the selected language is already saved.
- **Transfer limits:** the upload acknowledgement window is 256 KiB; high-latency throughput may be lower than an unconstrained pipeline. Cancellation/loss tests use a controlled loopback relay and OpenSSH on Windows/Ubuntu WSL, rather than every physical WAN failure. A stuck transfer's dedicated connection is closed; retry starts from zero. Remote temporary files can remain if cleanup cannot reach the server.
- **Updates:** manual installation. There is no automatic updater or telemetry. The beta is not signed with a trusted publisher certificate; Windows may display an unknown-publisher/SmartScreen prompt. Obtain it from a trusted release source. Do not disable operating-system protection.
- **Network Tools:** Linux ICMP without raw-socket permissions requires system iputils-ping. Traceroute/MTR uses ICMP TTL, with rate-limit/filtering caveats. TLS inspection does not check revocation or audit all protocols. HTTP responses are bounded to 2 MiB; SNMP WALK to 2000 OIDs. Secure collections require an unlocked OS credential store. Network Tools and Net-SNMP v3 were tested on Windows and Ubuntu/WSL; physical WAN routes and hardware WoL were not comprehensively tested. See [all limits](network-tools.md).

- **Commands:** own templates require an unlocked OS credential store. Import/export is JSON v1; YAML is not supported. Multiline scripts and secret parameters are copy-only. Automatic shell detection describes the login interpreter, not nested shells/editors/REPLs; verify the current program and empty input line before Execute. Tool presence does not prove version/permissions/plugin compatibility. Windows SSH has parser/channel fixtures but no new real Windows SSH server acceptance; the real network fixture is OpenSSH Linux. RDP/VNC/Serial remain browse/manual only. [Full guide and limits](commands.md).

Please include version, OS, language and a minimal reproduction when reporting a problem. Do not include secrets or unredacted connection data.

- **Plugins (0.39.0):** Linux monitoring and Commands are built-in modules controlled under Settings → Plugins. Toggle changes apply after Save without restart; stored snippets/settings are preserved. External plugin packages/DLL loading and a public plugin SDK are not implemented. [Guide](plugins.md).
