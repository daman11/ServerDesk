# RDP — osadzony Windows i klient zewnętrzny Linux

FreeRDP nie oferuje gotowej kontrolki Avalonia. Dokumentacja udostępnia framebuffer `rdpGdi.primary_buffer`, stride i rozmiary, a klienci SDL pokazują kopiowanie klatek do obrazu. Integracja jest technicznie możliwa przez natywny bridge FreeRDP 3, który zarządza kontekstem, uwierzytelnianiem, certyfikatami, input i clipboard. UI Avalonia mogłoby kopiować klatki do WriteableBitmap, bez osadzania obcego okna.

Od 0.15.0 WindowsRdpHost osadza systemowy ActiveX RDP w Avalonia NativeControlHost, przez AtlAxWin. Własny ukryty HWND utrzymuje kontrolkę podczas odłączenia od drzewa wizualnego. Test rzeczywistego lokalnego konta potwierdził OnLoginComplete, obraz pulpitu, podział widoku, przenoszenie do osobnego okna i z powrotem, zachowanie sesji przy przełączaniu kart, resize, reconnect i zamknięcie aplikacji. Stare profile pozostają w trybie mstsc. Linux nadal korzysta z zewnętrznego FreeRDP.

Nie wdrożono P/Invoke struktur FreeRDP o zależnym ABI. Docelowy adapter Linux powinien publikować frame + dirty rectangles, przesyłać klawiaturę/mysz, zmiany rozdzielczości i żądania certyfikatu przez kontrolowane callbacki. Pamięć klatek należy kopiować pod synchronizacją. Osadzanie obcego okna X11 nie rozwiązuje Wayland, dlatego potrzebny jest niezależny framebuffer. FreeRDP i WinPR wymagają przypiętych wersji oraz odpowiednich binariów. RDP Gateway, multimedia i obsługa macOS są przyszłym zakresem.

Hasło osadzonego klienta trafia w pamięci do write-only ClearTextPassword; nie do parametrów procesu ani plików. NLA pozostaje włączone, AuthenticationLevel=2 zachowuje systemowe ostrzeżenie o niezaufanym certyfikacie. Nie dodajemy certyfikatu do Windows ani nie wyłączamy weryfikacji globalnie. Połączenie jest potwierdzone dopiero przez OnLoginComplete, odrębnie od transportu i procesu. Od 0.16.0 sprawdzono tekst, obraz, pliki przez schowek, jego wyłączenie i autoreconnect po rzeczywistym przerwaniu transportu. Wykonane oraz pozostałe przypadki opisuje [pełna macierz](rdp-test-matrix.md); konta domenowe/Microsoft, szersze zaufanie certyfikatów i długie sesje nadal wymagają osobnych testów.

Źródła interfejsów: [Avalonia NativeControlHost](https://docs.avaloniaui.net/docs/app-development/native-interop), [AuthenticationLevel](https://learn.microsoft.com/en-us/windows/win32/termserv/imsrdpclientadvancedsettings4-authenticationlevel), [zdarzenia Microsoft RDP](https://learn.microsoft.com/en-us/windows/win32/termserv/imstscaxevents-interface). Komponent Windows pochodzi z systemu i nie jest redystrybuowany w paczce ServerDesk.
