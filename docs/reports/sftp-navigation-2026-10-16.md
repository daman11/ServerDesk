# SFTP navigation and confirmed paths — 2026-10-16

The 0.33.0 change adds in-memory local/remote directory history, navigation buttons and keyboard commands. DirectoryNavigationHistory retains up to 100 entries and previews a revision-bound target without moving the cursor. A successful read commits either that target or a new branch; refreshes, failures and superseded requests do not remove a forward branch. Local paths use the platform's comparison rule and remote paths remain ordinal/case-sensitive. Reconnect/close clears both histories and loaded entries.

RefreshAsync captures both path inputs before waiting on the existing refresh gate, checks them again before reading/publishing, normalizes local paths and commits resolved remote directories. Failure restores unchanged inputs to their previous confirmed values; a newer edit is preserved. The two panels still load together. Lists are disabled synchronously on an unconfirmed text property change and while reads are pending. Transfer/new-directory/link destinations require the loaded directory rather than draft text. The existing transfer snapshot and overwrite rules remain in place.

Nine new unit cases pass with the existing suite: 512/512, no skips. They cover side-effect-free previews, back/forward, refresh, branching, stale targets, changed resolved paths, capacity/clear, case rules and invalid paths. The headless layout scenario checks PL/EN, Graphite/Light, font16, both panels at 280/520/1000 px, disconnected controls, Ctrl+L and non-overlapping navigation buttons. Representative narrow-panel screenshots were inspected. The offline scenario opens no server and is included in Windows/Linux CI.

Actual OpenSSH/SFTP acceptance passes on Windows and Ubuntu/WSL using only the disposable loopback fixture: separate histories, Back/Forward/Up/Home buttons, Alt+Right, failed local/remote paths, retained forward navigation, Escape/path focus, refusal to upload into an unconfirmed path, UTF-8 byte roundtrip, superseded queued navigation and reconnect reset. It checks that no file appears at a rejected draft destination and removes only its GUID-scoped remote fixture. These are synthesized control/key events, not a physical keyboard matrix.

Windows regression passes for large-file views, protocols, session lifecycle/chrome and real SFTP resilience: cancelled silent upload/download, dropped overwrite preserving the original, transfer-slot recovery, complete 5000-file listing and retained filtered selection. The directory refresh measured 294 ms in this bounded fixture; it is not a WAN or endurance benchmark. The UI wait helper now throws after its deadline instead of blocking on an incomplete task. MainWindow's production SSH key verification is unchanged; only the test's own loopback factory accepts the disposable fixture key.

No application dependency, schema or credential-store change. History contains only directory paths in pane memory; it is not logged, saved or exported. Existing known issues still apply, including remote temporary files after network loss, physical desktop/keyboard/DPI coverage and Linux RDP's external client. Evidence: artifacts/reports/mvp-sftp-navigation/.
